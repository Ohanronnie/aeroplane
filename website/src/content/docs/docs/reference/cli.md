---
title: CLI
description: Deploy and inspect Aeroplane services from a terminal.
---

The Aeroplane installer adds the `aeroplane` command to `/usr/local/bin`. When it runs on the Aeroplane host, it connects to `http://127.0.0.1:4310` automatically and uses the root-only local credential generated by the installer.

## Run a repository

Create or update a service, deploy it, stream its build logs, and print its public URL:

```bash
aeroplane run acme/api expose 3000
```

The equivalent flag form is:

```bash
aeroplane run acme/api --expose 3000
```

Common options:

```bash
aeroplane run acme/api \
  --expose 3000 \
  --project backend \
  --name api \
  --branch main \
  --root apps/api
```

Running the same command again updates the matching service instead of creating a duplicate.

Use a GitHub PAT with repository webhook administration permission to deploy future pushes:

```bash
export AEROPLANE_GITHUB_TOKEN=github_pat_...
aeroplane run acme/api --expose 3000 --watch
```

The CLI registers the repository webhook and exits after deployment. GitHub sends later push events directly to Aeroplane, so no watcher process or polling loop needs to remain active. When the host-level `GITHUB_ACCESS_TOKEN` is configured, the environment variable can be omitted.

## Inspect and deploy services

```bash
aeroplane status
aeroplane status api
aeroplane deploy api
aeroplane logs api
```

Service names must be unique across the projects visible to the current credential. When names overlap, use the service ID shown by the API.

## Connect remotely

Create a read/write API key from **System Settings → API Access**, then save the remote connection:

```bash
aeroplane connect https://pilot.example.com --api-key ap_...
```

The connection is stored at `~/.config/aeroplane/config.json` with permissions limited to the current user. For CI, provide credentials without writing a configuration file:

```bash
export AEROPLANE_URL=https://pilot.example.com
export AEROPLANE_API_KEY=ap_...
aeroplane run acme/api --expose 3000
```

Command flags override environment variables, and environment variables override the saved connection.

## External Caddy

When another application already owns ports 80 and 443, install Aeroplane without starting its bundled Caddy:

```bash
curl -fsSL https://get.aeroplane.run | \
  AEROPLANE_MANAGE_CADDY=false \
  AEROPLANE_CADDY_CONFIG_PATH=/opt/aeroplane/data/Caddyfile \
  AEROPLANE_CADDY_DATA_DIR=/opt/aeroplane/data \
  AEROPLANE_CADDY_RELOAD_CMD='docker exec edge-caddy caddy reload --config /etc/caddy/Caddyfile' \
  sh
```

The external Caddy configuration must import the generated Aeroplane Caddyfile and mount the configured data directory at the same absolute path inside its container.
